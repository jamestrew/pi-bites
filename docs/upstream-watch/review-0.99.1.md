# Pi upstream review: 0.84.0 → 0.99.1

Date: 2026-09-30. Checkpoint remains **0.84.0** (2026-08-07); acceptance was not requested.
The helper fetched the published npm changelog: 12 releases, 380 individual bullets, including repeated feature summaries.
Local development dependencies are **0.87.1**, while the installed CLI is **0.99.1**. Changes through 0.87.1 are largely already incorporated; this is not a claim that all 380 changes still require migration.

Source: [fetched changelog](latest.md). The ledger below classifies every bullet in source order. Each non-ignore row references a finding containing local evidence and the next action. Quoted upstream documentation paths in the source are upstream paths, not this repository's `docs/`.

## Adapt

### A1 — New default model misses adapter activation (0.99.1)

Upstream adds `gpt-6.1-sol` and makes it the OpenAI Codex default.
`packages/ext/codex-adapter/activation.ts:34` accepts `gpt-5.6` or `gpt-6` followed by hyphen segments, but not `gpt-6.1-sol`. Thus the new default silently uses ordinary tools rather than the adapter's exec/wait projection. This is a confirmed scope gap, not an upstream API removal.

**Next:** explicitly decide support for GPT-6.1, extend the bounded model matcher and its tests if supported, and update the supported-model description in `README.md`. Do not indiscriminately enable every future GPT model.

### A2 — New OpenAI subscription login needs an explicit support policy (0.99.0–0.99.1)

Upstream introduces `/login openai`, labels the old Codex provider “legacy,” and fixes bundled login in 0.99.1. It does not remove the `openai-codex` identifier.
`packages/ext/token-count/index.ts:303-305` only accepts Copilot or `openai-codex`; subscription usage disappears for `openai`. `packages/ext/codex-adapter/web-run/tool.ts` trusts only stock `openai-codex` automatically; other providers require an exact allowlist or independent fallback opt-in. `README.md` describes this old route accurately, but not the new subscription option.

**Next:** document the new login's unsupported usage/search behavior, or add separately verified auth-aware support. Never treat all `openai` API-key models as ChatGPT accounts or send their credentials to the legacy usage/search endpoint automatically. Existing legacy-provider users need no forced migration.

### A3 — `--no-extensions` now disables built-ins too (0.99.0)

`package.json` runs development with `pi -ne -e ./packages/ext/index.ts`; this now excludes native MCP/codemode/tool-search and llama.cpp. `packages/ext/subagents/agent-runner.ts` also uses `noExtensions` and an explicit extension allowlist, but SDK sessions do **not** load native codemode/tool-search/MCP by default. This is a concrete CLI development-command change, not evidence that existing SDK subagents suddenly lost those built-ins; SDK effects require explicitly supplied builtin factories.

**Next:** document the development command as isolated, or explicitly add the desired `-e builtin:<name>` entries. Smoke-test child model/provider inheritance separately; do not broadly enable all built-ins inside isolated subagents.

## Leverage

### L1 — Native tool orchestration, not a wholesale runtime replacement (0.99.0)

Upstream adds native codemode/MCP, exposure/loadout APIs, `ctx.executeTool()`, structured results, and nested-call usage accounting.
Local `packages/ext/codex-adapter/code-mode/nested-adapters.ts` directly invokes a fixed set of five owned tools. `code-mode/tools.ts` registers **exec/wait**, not **codemode**: there is no direct name collision, but native codemode can coexist and MCP tools do not automatically enter local `ALL_TOOLS`. Missing `exposure` defaults to direct, making these local orchestrators callable by native codemode too.

**Next:** on a 0.99.1 dependency upgrade, consider `exposure: "model-only"` for exec/wait to prevent accidental nested orchestration. Evaluate `ctx.executeTool()` as the shared execution seam for normal hooks, nested events, persistence, and usage; preserve bash authorization, tool allowlists, cancellation, and ephemeral-context safety. Use native `isError` results where appropriate rather than the local error-marking hook. Do not replace the V8 yielding-cell runtime with QuickJS: exec/wait and persistent execution semantics differ. Keep structured shell output distinct from model-facing truncation; native output now reaches 1 MiB with a retrievable full-output path.

### L2 — Canonical sessions and compaction improvements, mostly already adopted (0.84.2–0.87.1)

Upstream adds restored in-memory sessions, context edits, actionable boundaries, failure events, per-model budgets, and fixes compaction, custom-message ordering, and cancellation.
`packages/ext/subagents/agent-runner.ts` already restores with `SessionManager.inMemory`; `subagents/fork-history.ts` uses `buildSessionProjection` and handles system messages rather than copying raw context edits. `goal/goal-runtime-events.ts` already consumes `session_compact_failed`; `goal/test/support/runtime-harness.ts` constructs boundary events. `subagents/subagent-messages.ts` and `at-mention-context/index.ts` rely on non-triggering custom messages. `goal` filters ordinary context without requiring system messages.

**Next:** retain those canonical paths and existing ordering tests. Goal continuation deliberately runs from `agent_end`; changing it to a new boundary is not automatically equivalent. The auto-compaction code reads, rather than assigns, `agent.state.messages`, so canonical ownership alone does not establish a break; no 0.99.1 private-seam failure was confirmed. Review `packages/ext/auto-compaction.ts` separately: it still patches `prepareNextTurnWithContext` and private `_runAutoCompaction`, and contains an older-runtime cancellation workaround. Compare native budgets/turn boundaries against the local fixed 150k threshold before deleting anything: reserve/recent-token budgets are not necessarily an equivalent threshold. Ensure threshold compaction, cancellation during auth, context edits, fork/resume, and settled continuation each remain covered on the upgraded runtime. Do not change to `context_with_system` unless a handler actually needs to transform system messages.

### L3 — Registry-backed streaming and public hook types (0.84.3, 0.86.0)

Upstream exposes authenticated `modelRegistry.stream/streamSimple`, provider-neutral tool choice, and missing hook types.
`packages/ext/automode/index.ts` and `session-tracker/index.ts` already use `streamSimple`; `goal/goal-runtime-event-handler-types.ts` uses exported event unions.

**Next:** keep these APIs; no manual authentication rewrite is needed. Use exported event types instead of new compatibility declarations when touching adjacent code.

### L4 — Shared clipboard implementation (0.84.2, 0.86.0–0.86.1)

Upstream improves asynchronous clipboard backends, WSL/container fallback, and truthful failure reporting.
`packages/ext/goal/clipboard.ts` independently spawns pbcopy/clip/PowerShell/wl-copy/xclip/xsel and does not inherit these fixes.

**Next:** evaluate the public clipboard helper and its success/failure contract before replacing the local implementation. Preserve the five-second timeout and truthful result; do not assume an OSC 52 write proves the clipboard changed.

### L5 — Approval and prompt observability (0.84.1, 0.84.4)

Upstream adds terminating blocked calls and UI prompt start/end events.
`packages/ext/bash-gate/authorization.ts` already propagates optional `terminate`; the direct `tool_call` catch in `bash-gate/index.ts` returns a normal blocked result. `session-tracker/index.ts` and `notifications.ts` track custom approval events and agent lifecycle, not general UI prompts.

**Next:** preserve ordinary recoverable denials; use terminate only for explicit terminal policy decisions. Consider UI prompt events if the tracker should represent non-bash UI waiting; do not replace domain-specific approval tracking wholesale.

## Watch

`packages/ext/footer/index.ts`, `statusline.ts`, `context.ts`, `view/index.ts`, `file-search/index.ts`, and tool renderers consume host TUI/theme behavior. No production custom editor embedding was found. The custom footer does not automatically acquire the host footer's new usage cache.

**Next:** smoke-test dark/light/system themes, narrow widths, overlays, image output, and theme changes on 0.99.1. Keep semantic custom tool summaries; upstream generic key=value fallback does not replace the repository's renderer grammar. Adopt new style APIs only when they remove real local complexity.

### W2 — Provider transports, model catalogs, and model settings (0.84.1–0.99.0)

Upstream changes model availability/defaults, auth, reasoning replay, strict-schema compatibility, streaming, cache routing/pricing, retry classification, and proxy handling.
`packages/ext/subagents/model-resolver.ts`, `parent-snapshot.ts`, and `agent-runner.ts` use host model/runtime metadata; `small-model.ts` selects a configurable model with a Haiku default. `automode/index.ts` and `session-tracker/index.ts` make registry-backed calls. There is no local implementation of the listed provider adapters to patch. No production reference to the removed GPT-5.4 models was found. Provider stream normalization also affects test providers: inspect `packages/ext/subagents/test/helpers/v2-harness.ts` and `print-mode-runner.ts` when upgrading.

**Next:** take host fixes with the dependency upgrade; smoke-test configured providers, reasoning, retries, and inherited model settings. Do not copy upstream adapter workarounds locally. New models other than A1 do not require a local catalog edit. Preserve source provider identity in diagnostics and session affinity in side calls.

### W3 — Packaging, registration, and diagnostics (0.84.1–0.99.0)

Upstream improves extension loading, source identifiers, peer dependency handling, compiler/startup behavior, flag/schema validation, settings warnings, unsubscribe support, and bug reports.
`package.json` already keeps pi modules in peer/dev dependencies, not production dependencies. It pins pi packages to 0.87.1 and includes `pi-server`; production source searches found no pi-server or experimental client imports. `packages/ext/index.ts` registers the collection; `tools.ts` deliberately replaces built-in tool definitions. Flag defaults in `bash-gate/index.ts` and `file-search/index.ts` use declared types. `subagents/runner-diagnostics.ts` consumes host lifecycle diagnostics.

**Next:** upgrade the development pins deliberately using `scripts/update-pi.sh`, then run the complete checks and extension-load smoke test against 0.99.1. Expect intentional replacement warnings, not an exec/codemode collision. Avoid parsing old `<builtin:...>` source labels. Use unsubscribe only for genuinely dynamic handlers. Review transcript inclusion before sharing `/bug` reports; host redaction is not a guarantee that custom message contents are nonsensitive.

### W4 — Built-in tools, schemas, cwd, and output limits (0.84.1–0.99.0)

Upstream fixes builtin cwd handling, edit normalization, signal exits, optional read rendering, images, tool downloads, and default-tool selection; tightens JSON result types and enables strict-prefer sampling.
`packages/ext/tools.ts` wraps read/edit/bash definitions and intentionally owns a different edit schema; `at-mention-context/index.ts` uses read/ls factories with explicit cwd; adapter tools own separate execution/truncation. `spotme/index.ts` and adapter activation alter active tools. Tools already declare schemas. No PowerShell authorization policy was found alongside the bash gate.

**Next:** retain custom edit semantics rather than blindly adopting the upstream edit input shape. Validate child cwd, JSON-compatible details, strict sampling, selected tool preservation, signal exits, null read options, and image inputs during upgrade. Do not assume native PowerShell is protected by the bash gate; add a policy before advertising it as approved shell execution. Builtin fixes do not automatically fix owned native adapter commands.

### W5 — Inputs, skill discovery, and prompt updates (0.84.2–0.99.0)

Upstream fixes skill/path autocomplete, frontmatter discovery, template warnings, RPC input dispatch, and leading system prompts; adds explicit template expansion for extension messages.
`packages/ext/inline-references/index.ts` owns dollar/skill autocomplete; `at-mention-context/index.ts` reads referenced paths; `ponytail/index.ts` and `prompt-normalization/index.ts` transform input. `packages/ext/index.ts` composes prompt previews. Skills are loaded from `packages/ext/ponytail/skills` and `.agents/skills`.

**Next:** test those wrappers against inherited completion fixes, especially brackets, backticks, and CJK boundaries. Keep generated goal/spotme text literal unless expansion is explicitly intended; `expandPromptTemplates` should not become an unconditional default. Re-run input transformations for RPC steering/follow-up scenarios.

### W6 — Usage and hidden transcript data (0.84.2–0.99.0)

Upstream fixes usage/pricing and streaming metadata, records sessions on first user input, exposes hidden custom messages in HTML exports, and includes new tool/classifier costs.
`packages/ext/subagents/usage.ts` and `agent-runner.ts` accumulate assistant usage; `usage-dashboard-data.ts`, `footer/index.ts`, and `goal/goal-accounting.ts` report/account for it. `subagents/agent-runner.ts` stores hidden continuations and other extensions use `display: false`.

**Next:** treat hidden messages as presentation-only, not confidential export storage. If native classifier/nested model tools are enabled, audit assistant-only totals against host session totals so tool-result usage is not omitted or double-counted. Existing cache/pricing corrections are inherited, not a reason to invent local prices.

### W7 — New model/runtime and scheduling capabilities (0.86.0, 0.99.0)

Upstream adds virtual/classifier/image models, input dispositions, provider stream events, and cache warming controls.
`packages/ext/small-model.ts` and `automode/index.ts` use ordinary chat decisions; `subagents/agent-runner.ts` registers inherited providers, sends steering, and instruments payload/response hooks. No local classifier, image-generation, or virtual-model registration was found.

**Next:** keep chat accessors where chat models are required; assess new operation types only for a concrete feature. If adopting virtual routing, recheck adapter activation and usage attribution to the physical model. Consider input dispositions for delivery acknowledgements and provider events for diagnostics; cache warming may create billable side requests, so evaluate settings rather than assuming every request is task progress.
